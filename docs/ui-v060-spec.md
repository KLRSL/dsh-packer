## 2. 页面结构（一页，五个区块，从上到下）

1. **标题区**：标题「配置打包器」，副标题「把本机的 DSH 配置打包备份，换机器或换平台时恢复」。
2. **已有的配置包**（列表）：列 = 包名 / 时间 / 内容（几项·几文件）/ 大小 / 是否加密 / 操作（恢复、包信息、删除）。空态：一句「还没有配置包。点下方「开始打包」生成第一个（约 37 MB）」。
3. **打包内容**：表格列 = 内容 / 说明 / 体积 / 是否带上（勾选）。行：技能库、已安装插件、记忆数据库、会话记录、配置与预设。表格下：合计体积 + 一句提醒（换机器必须带已安装插件；只给别人时去掉会话/插件/记忆/配置）。
4. **打包选项**：三个 checkbox（原样打包 / 清理后打包（脱敏）/ 加密（设置口令））+ 口令输入（勾加密才出现）+ 扫描结论 alert + 「开始打包」「先预览」按钮 + 进度条与取消。
5. **恢复**：选择配置包（下拉，来自列表）+ 或填路径 → 「导入检查」→ **差异对比**表（内容 / 包内 / 本机 / 处理方式）→ 模块勾选 + 「连记忆数据库一起恢复（需先退出 DSH）」→ 三个策略 → 「开始恢复」→ 进度 → **恢复结果**明细（覆盖/新增/跳过/待确认/失败）+ 备份目录 + 一键撤回。
6. **结果区**（打包与恢复共用样式）：表格列 = 结果项 / 数量 / 说明；底部固定两行：保存路径（可复制）、SHA-256 指纹。

## 3. 文案纪律

- **禁止 emoji 与图标字符**（✓、⚠、📦 等一律不用）：状态用文字（已带上/相同/跳过/待确认/已加密）与 CSS 细线、色块表达。
- 不出现字段名（`memoryDb`、`presets`、`pack` 这类）；用产品语言（记忆数据库、配置与预设）。
- 中文单语；数字与单位统一（KB/MB，保留一位小数）。
- 每个按钮的落点必须真实：开始打包 → `POST /create`；先预览 → `POST /create {dryRun}`；进度/取消 → `GET /jobs/:id`、`POST /jobs/:id/cancel`；恢复 → `POST /restore/import` / `/restore/apply`；撤回 → `POST /restore/rollback`；删除 → `DELETE /packs/:name`（说明进 Windows 回收站）；包信息 → `GET /packs/:name/info`（含完整性校验结果）；改名 → `POST /packs/rename`。
